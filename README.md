# bible

Read Bible translations from the command line or in a browser-based viewer.
It is a single self-contained binary with the translations database
embedded in it: no runtime, no libraries and no files to install alongside
it.

```
bible matt 5:3                    # print a verse
bible 1cor 13:4-7 t:all           # in every translation
bible -s "faith b:romans t:kjv"   # search
bible gui                         # open the viewer in your browser
```

## Prebuilt binaries

You can download a stand alone prebuilt binaries generated by [a github workflow](.github/workflows/release.yml).

The binaries can be found under [releases](https://github.com/JCallicoat/bible/releases).

## Building

You need Go 1.26 or newer.

1. Copy your `bible.db` to `data/bible.db`. It is embedded at build time;
   the build fails with "pattern bible.db: no matching files found" if it
   is missing.
2. Build:

   ```
   make build        # or: CGO_ENABLED=0 go build -trimpath -ldflags="-s -w" -o bible .
   ```

3. Optionally, add paragraph data first (see [Paragraphs](#paragraphs)):

   ```
   make build-paragraphs EMBED_URL=http://127.0.0.1:8080
   ```

`make release` cross-compiles for Linux, macOS (amd64/arm64) and Windows
into `dist/`. Builds use no cgo, so any platform can build all of them.

The binary is about 12 MB plus the size of `bible.db`. SQLite reads the
embedded database in place (through the `readervfs` VFS of
[ncruces/go-sqlite3](https://github.com/ncruces/go-sqlite3)), so it is never
copied into memory or extracted to disk; a lookup typically runs in
10 to 40 ms.

## Command line

```
bible [options] [book [chapter[:verse[-verse]]] [filters...]]

  -L, --lines                Print one verse per line instead of grouping verses into paragraphs
  -l, --list                 List available translations
  -t, --translation string   Translation code(s), comma separated, or "all" (default "NRSVUE")
  -s, --search string        Search verse text for a regular expression
  -f, --fixed-strings        Search for the literal text instead of a regular expression
  -i, --ignore-case          Ignore case when searching
  -w, --wrap int             Wrap output lines at the last space before this column (0: no wrapping)
```

With no arguments it prints Genesis 1. Books can be abbreviated to any
unambiguous prefix (`1cor`, `song`, `philem`). Lookups and searches accept
`t:<translation>` / `t:all` filters, and searches also accept `b:<book>`.
Options can appear anywhere on the line (`bible matt 5:3 -t kjv`). Lookups
are grouped into paragraphs when the database has paragraph data (see
[Paragraphs](#paragraphs)). Each paragraph is one line that starts with the
reference of its first verse, with later verses numbered inline:

```
Genesis 1:1 When God began to create the heavens and the earth, (2) the earth was complete chaos, ...
```

`-L` (or `--lines`) prints one verse per line instead, as does a database
without paragraph data. Search results are always one verse per line.

Searches use [Go regular expressions](https://pkg.go.dev/regexp/syntax)
(RE2 syntax, so no backreferences or lookarounds) and are case-sensitive.
`-i` (or `--ignore-case`) ignores case, and `-f` (or `--fixed-strings`)
matches the text literally, for searching for characters like `.` or `(`.
Filters are taken out first, so a pattern can't contain a word starting
with `b:` or `t:`.

```
bible -s "love(th|s) b:1john t:kjv"   # "loveth" or "loves"
bible -s "^In the beginning"          # at the start of a verse
bible -i -f -s "lord."                # "lord." or "Lord.", literally
```

`-w N` (or `--wrap N`) wraps long lines for reading in a terminal: each
line is broken at the last space before column N, so no line is N or more
characters long unless a single word is. For example, `bible -w 80 gen 1`.

Translation names, references and verse numbers are printed in bold, as are
matches of the search text in search results. Bold is used only when
output goes to a terminal, and never when the `NO_COLOR` environment
variable is set to a non-empty value.

## Viewer

`bible gui` starts a small web server on 127.0.0.1 (on a free port) and
opens the viewer in your default browser. It has translation, book and
chapter dropdowns, a lookup box, a search box and the text view. After a
lookup with `t:<translation>`, the dropdowns switch to that translation and
its books. Searches are case-sensitive regular expressions, like the
command line; uncheck **Regex** to search for the literal text, and check
**Ignore case** to ignore case.

The server stops on its own about 3 seconds after you close the last tab
showing it (reloading the page is fine), or when you click **Quit**. If no
tab connects within 30 seconds of launch, it stops too.

```
bible gui --no-browser    # just print the address; stop with Ctrl+C
bible gui --port 8080     # use a fixed port
bible gui -L              # one verse per line instead of paragraphs
```

Chapters and lookups are shown as paragraphs, like the command line.

Keyboard shortcuts (Cmd works in place of Ctrl on a Mac):

| Keys    | Action            |
|---------|-------------------|
| Ctrl+L  | Lookup            |
| Ctrl+S  | Search            |
| Alt+T   | Translation       |
| Ctrl+B  | Book              |
| Ctrl+K  | Chapter           |
| Ctrl+D  | Text view         |
| Alt+Q   | Quit              |

Translation and Quit moved from Ctrl+T and Ctrl+Q to Alt because browsers
don't let pages override those two.

On Windows the binary is a console program, so a console window stays open
while the viewer runs.

## Paragraphs

Paragraph breaks are computed once, from the KJV, and used for every
translation (books are matched by name). They live in a small
`paragraphs` table in `bible.db` (one row per chapter listing the verses
that start a paragraph, about 40 KB), generated by a build-time command
that isn't listed in `bible --help`:

```
bible embed-paragraphs --db data/bible.db \
    --embed-url http://127.0.0.1:8080 --embed-model MODEL [--embed-api-key KEY]
```

It sends every KJV verse to an OpenAI-compatible `/v1/embeddings`
endpoint, in batches of `--batch` (32) with `--parallel` (4) requests at a
time. `--embed-url` can be the server's base URL or the full
`.../v1/embeddings` URL. It then places breaks where the meaning shifts
most between neighbouring verses (comparing `--window` verses on each
side). It writes the table, replacing any existing one, and vacuums the
database. Then rebuild to embed the new database.

`make paragraphs` runs the command on `data/bible.db`, and
`make build-paragraphs` runs it and then builds. Both take `EMBED_URL`,
`EMBED_MODEL` and `EMBED_API_KEY`, plus `EMBED_FLAGS` for any other options.
For example, with llama.cpp and a local embedding model:

```
llama-server -m Qwen3-Embedding-0.6B-Q8_0.gguf --embeddings --pooling last \
    -np 4 -c 8192 -ub 2048 -b 2048
make build-paragraphs EMBED_URL=http://127.0.0.1:8080
```

That takes a couple of minutes on a desktop GPU. To tune the breaks
without embedding again, pass `--embed-cache FILE`: the first run saves the
embeddings there (about 190 MB for a 1024-dimension model) and later runs
load them. These options control the breaks:

| Option         | Default | Meaning                                    |
|----------------|---------|--------------------------------------------|
| `--avg-verses` | 6       | target average paragraph length, in verses |
| `--min-verses` | 2       | shortest allowed paragraph                 |
| `--max-verses` | 20      | longest allowed paragraph (0: no limit)    |
| `--window`     | 3       | verses compared on each side of a break    |

```
make paragraphs EMBED_FLAGS="--embed-cache /tmp/kjv.emb --avg-verses 8"
```

## Development

A hidden `--db PATH` option (on both `bible` and `bible gui`) reads a
database file instead of the embedded copy, for trying a new `bible.db`
without rebuilding.

Layout:

```
main.go                 dispatches "gui" vs. the CLI
data/                   embeds bible.db (go:embed can't reach parent directories)
internal/bible/         shared logic: database, filters, references, lookup, search, suggestions
internal/cli/           command-line interface
internal/web/           viewer: HTTP API, auto-shutdown, browser launch
internal/web/static/    the page (HTML/CSS/JS), embedded
internal/paragraphs/    embed-paragraphs: builds the paragraphs table from embeddings
```
